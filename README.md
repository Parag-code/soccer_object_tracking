# Soccer Object Tracking

A computer vision project for detecting and tracking objects in a soccer match video using YOLO, ByteTrack, and BoT-SORT with Re-Identification (Re-ID) and Global Motion Compensation (GMC).

The project implements an end-to-end tracking pipeline, compares ByteTrack with BoT-SORT + Re-ID + GMC, analyzes tracking persistence using frame-level tracking data, and generates a final trajectory visualization.

---

## Project Overview

The goal of this project is to build a complete multi-object tracking pipeline for soccer footage.

The system first detects objects in the video using a football-specific YOLO model. The detections are then passed through two tracking approaches:

- ByteTrack as the baseline tracker
- BoT-SORT with Re-ID and GMC as the enhanced tracker

Tracking information is exported to CSV files and analyzed to compare the persistence and fragmentation of both approaches.

The final stage generates a visualization containing tracking IDs, bounding boxes, player trajectories, active track information, and frame information.

## Re-Identification

Re-Identification uses appearance information to improve the association of detections belonging to the same tracked object.

This can help maintain track identities when an object temporarily disappears or when spatial information alone is insufficient for reliable association.

In this project, Re-ID is enabled through:

```yaml
with_reid: true
model: auto
```

---

## Global Motion Compensation

Global Motion Compensation is enabled using sparse optical flow:

```yaml
gmc_method: sparseOptFlow
```

GMC helps compensate for camera movement when associating objects between frames.

## Track Persistence Analysis

Track persistence is analyzed using the frame range and observation count of each track ID.

The following metrics are calculated:

- Number of tracks
- Average observations per ID
- Average track duration
- Median track duration
- Longest track

### Results

| Metric | ByteTrack | BoT-SORT + Re-ID + GMC |
|---|---:|---:|
| Number of tracks | 73 | 63 |
| Average observations per ID | 240.62 | 278.00 |
| Average track duration | 243.60 | 280.38 |
| Median track duration | 31 | 28 |
| Longest track | 750 | 750 |

### Observation

For the selected sequence, BoT-SORT + Re-ID + GMC produced fewer unique tracks and higher average observations per ID and average track duration compared with ByteTrack.

This indicates better track persistence and reduced fragmentation in this particular experiment.

The results are sequence-specific and should not be interpreted as benchmark results.

## ByteTrack vs BoT-SORT

The two approaches were compared using the generated tracking data.

### ByteTrack

ByteTrack produced:

```text
73 unique tracks
240.62 average observations per ID
243.60 average track duration
```

### BoT-SORT + Re-ID + GMC

BoT-SORT produced:

```text
63 unique tracks
278.00 average observations per ID
280.38 average track duration
```

The results show that BoT-SORT maintained tracks for longer on average for the selected sequence.

The reduction in the number of unique track IDs together with the increase in average track duration suggests reduced track fragmentation.

However, ground-truth identity annotations were not available, so formal metrics such as IDF1, HOTA, and ID-switch count were not evaluated.

## Player Trajectory Visualization

The final visualization is generated using the BoT-SORT tracking CSV.

For each tracked object, the bottom-center point of its bounding box is used as the reference position:

```text
center_x = (x1 + x2) / 2
center_y = y2
```

A rolling history of recent positions is maintained for each track.

The trajectory configuration uses:

```text
Trajectory length: 30 frames
Maximum missing-frame gap: 2 frames
```

The visualization contains:

- Bounding boxes
- Track IDs
- Recent trajectories
- Active track count
- Frame counter
- Tracker information

## Limitations

- The experiment is performed on a selected soccer video sequence.
- Ground-truth identity annotations are not available.
- Formal IDF1, HOTA, and ID-switch metrics are therefore not reported.
- Tracking statistics are specific to the selected sequence.
- Tracking IDs represent algorithm-generated identities rather than verified player identities.
- The current implementation focuses on object detection and tracking rather than complete tactical analysis.
- Processing speed depends on available hardware.

## Conclusion

This project implements an end-to-end soccer object detection and multi-object tracking pipeline.

YOLO is used for object detection, ByteTrack provides the baseline tracking approach, and BoT-SORT with Re-ID and GMC provides the enhanced tracking approach.

The generated tracking data is stored in structured CSV files and analyzed using track persistence metrics. Player trajectories are then visualized using the BoT-SORT tracking results.

For the selected sequence, BoT-SORT + Re-ID + GMC generated fewer unique tracks and achieved higher average observations per ID and higher average track duration than ByteTrack.

This provides evidence of improved track persistence for the selected experiment while keeping the evaluation appropriately limited by the absence of ground-truth identity annotations.
